GOAL
----
- Get a working, modern C++ compiler on your Mac.
- Understand the three stages that turn .cpp files into a program.
- Know what the common compiler flags mean.
- Build and run the TradingEngine C++ server yourself.


PYTHON VS C++
-------------
Python: you run "python file.py". An interpreter reads your source every
time, and most errors show up while the program is running.

C++: you COMPILE source code into a native machine-code binary ahead of
time, then run that binary. The compiler checks types before anything runs,
so a huge class of bugs is caught early. The price: a build step, and
error messages you have to learn to read.


--------------------------------------------------------------------------------
1. SETUP (DO THIS FIRST)
--------------------------------------------------------------------------------

Your current state:
  - clang++ / g++  ->  Apple Clang 14   (too old: no std::format, no c++23)
  - cmake          ->  not installed
  - go             ->  not installed (only needed to run this repo's gateway)

Step 1: check what you have
    clang++ --version

Step 2 (preferred): update Apple's Command Line Tools
    softwareupdate --list
  Look for "Command Line Tools for Xcode-XX" and install it:
    softwareupdate -i "Command Line Tools for Xcode-XX"
  If that doesn't show anything, reinstall them:
    sudo rm -rf /Library/Developer/CommandLineTools
    xcode-select --install

Step 2 (alternative): Homebrew's LLVM
    brew install llvm
    $(brew --prefix llvm)/bin/clang++ --version
  Run "brew info llvm" and read the "caveats" section. It tells you which
  extra linker flags you need to use Homebrew's own C++ standard library.

Step 3: install CMake (the build system you'll use from lesson 14 on)
    brew install cmake

Step 4: verify with this test program. Save as check.cpp:

    #include <format>
    #include <iostream>

    int main() {
        std::cout << std::format("C++ version macro: {}\n", __cplusplus);
    }

    clang++ -std=c++20 check.cpp -o check && ./check

  If it prints a number like 202002, you're good. If you get
  "no member named 'format' in namespace 'std'", your compiler is still
  too old.

Step 5 (editor): in Cursor, install the "clangd" extension. It gives you
  real-time errors, go-to-definition, and autocomplete for C++.


--------------------------------------------------------------------------------
2. THE COMPILATION MODEL: THREE STAGES
--------------------------------------------------------------------------------

  source.cpp --[preprocessor]--> expanded source
             --[compiler]------> source.o   (object file: machine code)
  many .o files + libraries --[linker]--> executable

STAGE 1: THE PREPROCESSOR
  Lines starting with # are handled before real compilation.
    #include "httplib.h"    literally pastes the whole file's text in here
    #include <vector>       same, but searches the system include paths
    #define NAME value      text substitution (avoid for constants in C++)
    #ifdef / #ifndef        conditional compilation (used for OS-specific code)

  Important: #include is NOT like Python's import. It is copy-paste. If
  you include a 12,000-line header (httplib.h is 12,332 lines), the
  compiler processes all 12,000 lines every time. That's why Server.cpp
  takes several seconds to compile.

STAGE 2: THE COMPILER
  Each .cpp file (plus everything it #includes) is a "translation unit".
  The compiler turns one translation unit into one object file (.o).
  It only knows about things DECLARED earlier in that unit. That's why C++
  cares about order: you can't use a function before it is declared.

STAGE 3: THE LINKER
  Combines object files and libraries into one executable. If you declared
  a function but never defined it anywhere, you get a LINK error (not a
  compile error):
      Undefined symbols for architecture arm64: "foo()"
  Learning to tell compile errors from link errors saves you hours.

HEADERS VS SOURCE FILES (preview of lesson 14)
  .hpp / .h  = declarations ("this function exists, here's its signature")
  .cpp       = definitions  ("here's the body")
  Other files #include the header, and the linker connects them to the
  definitions. This repo puts everything in ONE .cpp file, so it never
  teaches this. You will do it properly in your project.

HEADER-ONLY LIBRARIES
  httplib.h is a "header-only" library: the entire library lives in the
  header, so there is nothing to link. C++ has no universal package
  manager like pip, so header-only libraries are popular because you can
  just drop the file in. (Real package managers exist: vcpkg, Conan, and
  CMake's FetchContent. More in lesson 14.)


--------------------------------------------------------------------------------
3. COMPILER FLAGS YOU MUST KNOW
--------------------------------------------------------------------------------

  -std=c++20        language version (c++17, c++20, c++23)
  -o server         name of the output file
  -O0 / -O2 / -O3   optimization level. -O0 for debugging, -O2 for release
  -g                include debug info (for debuggers and sanitizers)
  -Wall -Wextra     turn on warnings. ALWAYS use these.
  -Wpedantic        warn about non-standard extensions
  -Werror           treat warnings as errors (good for your own project)
  -I path           add a directory to search for #include files
  -l name           link a library (e.g. -lws2_32 = Windows sockets)
  -pthread          enable threads on Linux
  -fsanitize=address,undefined   runtime bug detectors (lesson 08)

"Debug build" usually means: -O0 -g -fsanitize=address,undefined
"Release build" usually means: -O2 (or -O3) -DNDEBUG


--------------------------------------------------------------------------------
4. main() AND COMMAND-LINE ARGUMENTS
--------------------------------------------------------------------------------

Every C++ program starts at main. It's like Python's
if __name__ == "__main__":, but required.

    int main(int argc, char* argv[]) {
        // argc = number of args (including the program name)
        // argv = array of C-style strings. argv[0] is the program name
        return 0;   // 0 = success, which the shell sees as the exit code
    }

Python equivalent: sys.argv (argv) and len(sys.argv) (argc).


IN THIS REPO
------------
  backend/engine/Server.cpp:1-18
    The #include list. "httplib.h" uses quotes (a local file). <vector>,
    <map>, etc. use angle brackets (the standard library).

  backend/engine/Server.cpp:863-889 (main)
    Reads the port from argv[1] with std::stoi, falling back to 6060. The
    Go gateway launches this binary with a different port per stock.

  start.sh:105-115
    Per-OS compile commands. Note the OS differences:
      macOS:   g++ -std=c++23 -O2 Server.cpp -o server
      Windows: ... -lws2_32 -o server.exe     (link Windows socket library)
      Linux:   ... -pthread -o server          (enable threads)

  compile.txt
    The author's notes, from a Windows machine (server.exe, -lws2_32).

  backend/engine/server
    A prebuilt macOS arm64 binary is committed to the repo. Committing
    build outputs is generally bad practice (it goes stale, and it only
    runs on one platform). Add build outputs to .gitignore in your project.


PITFALLS
--------
- Assuming "g++" on a Mac is GCC. It's Apple Clang in disguise.
- Ignoring warnings. The compiler flagged a real issue in this repo
  (see lesson 03) that nobody noticed because warnings weren't enabled.
- Reading only the LAST error message. Read the FIRST one. Later errors
  are often knock-on effects of the first.
- Forgetting to recompile. Unlike Python, editing the .cpp does nothing
  until you rebuild.


EXERCISES
---------
1. Complete the setup section and get check.cpp to run.

2. Build the repo's engine yourself (after setup):
       cd backend/engine
       clang++ -std=c++20 -Wall -Wextra -O2 Server.cpp -o server_mine
       ./server_mine 6070
   In another terminal:
       curl -X POST "http://localhost:6070/trade" \
         -d "orderid=1&tradetype=GTC&side=BUY&price=100&quantity=10&book=AAPL"
       curl http://localhost:6070/status
   Note which warnings -Wall -Wextra print. You'll understand all of them
   by lesson 08.

3. Cause a LINK error on purpose. In a new file:
       int add(int a, int b);        // declared, never defined
       int main() { return add(1, 2); }
   Compile it and read the error. Then add a definition and recompile.

4. See the preprocessor's output:
       clang++ -std=c++20 -E check.cpp | wc -l
   A 5-line program becomes tens of thousands of lines after #include.

5. Time the difference between -O0 and -O2 builds of Server.cpp:
       time clang++ -std=c++20 -O0 Server.cpp -o s0
       time clang++ -std=c++20 -O2 Server.cpp -o s2
