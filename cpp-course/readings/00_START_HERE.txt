WHAT THIS IS
------------
An ordered course that teaches you the parts of C++ that DON'T exist in
Python, using this repo (a stock order-matching engine) as the running
example. It ends with you designing and building your own version, with a
choice of what to use instead of Go for the gateway layer.

You already know programming. This course skips "what is a loop" and
focuses on the things that trip up Python developers: types, memory,
references, ownership, the compiler, and undefined behavior.


HOW TO USE IT
-------------
1. Read the lessons IN ORDER. Each one builds on the previous.
2. Every lesson has the same shape:
     GOAL           what you'll be able to do afterwards
     PYTHON VS C++  the one-paragraph mental model shift
     CONCEPTS       the actual material, with code
     IN THIS REPO   where to look in the TradingEngine code (file:line)
     PITFALLS       mistakes people make
     EXERCISES      small things to type and run (do them!)
     CHECKPOINT     questions you should be able to answer before moving on
3. Type the code yourself. Do not copy-paste. C++ is learned through
   compiler errors.
4. Keep a scratch folder (e.g. ~/cpp-scratch) for the exercises.
5. Keep the repo file open side by side:
     backend/engine/Server.cpp    <- the only C++ file (~890 lines)

BEFORE YOU START — YOUR MACHINE NEEDS A NEWER COMPILER
-----------------------------------------------------
Your Mac currently has Apple Clang 14. It does NOT support std::format or
-std=c++23, which this repo uses, so the repo will not compile as-is.
Also on macOS, the "g++" command is actually Apple Clang, not GNU g++.
CMake and Go are not installed either.

Lesson 01 walks you through fixing this. Do that first.


THE THREE MOST IMPORTANT IDEAS IN THIS COURSE
---------------------------------------------
If you remember nothing else:

  1. In C++, COPYING is the default. In Python, everything is a reference.
     You opt into references (&) and pointers (*) explicitly. (Lesson 04)

  2. Every piece of memory has an OWNER, and when the owner goes away the
     memory is destroyed, immediately and deterministically. (Lesson 05)

  3. If you touch memory after its owner destroyed it, the program has
     UNDEFINED BEHAVIOR: it might work, crash, or corrupt data, and it may
     behave differently on Windows vs macOS. This repo contains a real
     example of exactly that. (Lesson 08)
