GOAL
----
- Split C++ code into headers and source files correctly.
- Build a multi-target project with CMake (library, server, tests).
- Write unit tests with Catch2 and run them under sanitizers.
- Set up the project skeleton for your own order book.


PYTHON VS C++
-------------
Python: a folder of .py files, a pyproject.toml, "pip install", and
"pytest". Imports just work.

C++: you decide how files are compiled and linked, and a build system
(CMake) generates the actual compiler commands. There's no single package
manager. It's more setup, but you only do it once, and this lesson gives
you a template.

2. HEADERS AND SOURCE FILES
--------------------------------------------------------------------------------

HEADER (include/orderbook/orderbook.hpp): WHAT exists
    #pragma once                        // include this file only once per .cpp

    #include "orderbook/order.hpp"
    #include <vector>

    class Orderbook {
    public:
        std::vector<Trade> add(Order order);
        bool cancel(OrderId id);
        // ...
    private:
        // data members must be in the header: the compiler needs the
        // class's size wherever it's used
    };

SOURCE (src/orderbook.cpp): HOW it works
    #include "orderbook/orderbook.hpp"

    std::vector<Trade> Orderbook::add(Order order) {   // ClassName::method
        // ...
    }

RULES
  - #pragma once (or the older #ifndef/#define/#endif "include guard")
    at the top of every header.
  - Headers hold declarations, class definitions, templates, and inline
    functions. .cpp files hold the rest.
  - ONE DEFINITION RULE (ODR): a non-inline function may be defined in
    exactly one .cpp file. Defining one in a header that two .cpp files
    include gives a "duplicate symbol" link error. Fix: move it to a
    .cpp, or mark it inline.
  - Templates normally go in headers, because the compiler needs the full
    definition wherever it generates code for a new type. Exception: a
    private template that's only used inside one .cpp can live in that
    .cpp (the reference solution does this).
  - Never put "using namespace" in a header.
  - Include what you use: each file includes the headers it needs, and
    doesn't rely on another header pulling them in.

3. CMAKE
--------------------------------------------------------------------------------

CMake reads CMakeLists.txt and generates the build (Makefiles or Ninja).
Think of it as pyproject.toml plus a build tool.

  cmake_minimum_required(VERSION 3.20)
  project(orderbook LANGUAGES CXX)

  set(CMAKE_CXX_STANDARD 20)
  set(CMAKE_CXX_STANDARD_REQUIRED ON)
  set(CMAKE_EXPORT_COMPILE_COMMANDS ON)      # lets clangd understand the project

  option(ORDERBOOK_SANITIZE "Build with address + UB sanitizers" ON)
  if(ORDERBOOK_SANITIZE)
    add_compile_options(-fsanitize=address,undefined -fno-omit-frame-pointer)
    add_link_options(-fsanitize=address,undefined)
  endif()

  # the pure-logic library
  add_library(orderbook_core src/orderbook.cpp)
  target_include_directories(orderbook_core PUBLIC include)
  target_compile_options(orderbook_core PRIVATE -Wall -Wextra -Wpedantic -Werror)

  # the server
  add_executable(engine_server server/main.cpp)
  target_link_libraries(engine_server PRIVATE orderbook_core)

  # tests (Catch2 is downloaded automatically)
  include(FetchContent)
  FetchContent_Declare(Catch2
    GIT_REPOSITORY https://github.com/catchorg/Catch2.git
    GIT_TAG        v3.7.1)
  FetchContent_MakeAvailable(Catch2)

  add_executable(orderbook_tests tests/orderbook_test.cpp)
  target_link_libraries(orderbook_tests PRIVATE orderbook_core Catch2::Catch2WithMain)

  enable_testing()
  add_test(NAME orderbook_tests COMMAND orderbook_tests)

  Note: add_compile_options only affects targets defined AFTER it, which
  is why the sanitizer block comes first.

BUILDING
  cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug        # configure (once)
  cmake --build build                                 # compile
  ctest --test-dir build --output-on-failure          # run tests

  Release build, without sanitizers, in a separate folder:
  cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DORDERBOOK_SANITIZE=OFF
  cmake --build build-release

  PUBLIC vs PRIVATE in target_* commands: PUBLIC settings also apply to
  anything that links this target (the include path has to be PUBLIC so
  the tests can find the headers). PRIVATE settings apply to this target
  only.

GETTING OTHER LIBRARIES
  FetchContent (above)    downloads at configure time. Simplest.
  vcpkg / Conan           real package managers. Worth learning later.
  Homebrew + find_package e.g. brew install nlohmann-json, then
                          find_package(nlohmann_json CONFIG REQUIRED)
  Single-header drop-in   like httplib.h in this repo.

4. UNIT TESTS WITH CATCH2
--------------------------------------------------------------------------------

  // tests/orderbook_test.cpp
  #include <catch2/catch_test_macros.hpp>
  #include "orderbook/orderbook.hpp"

  TEST_CASE("crossing orders produce trades at the resting price") {
      Orderbook book;
      REQUIRE(book.add({1, Side::Sell, OrderType::GoodTillCancel, 100, 5}).empty());

      auto trades = book.add({2, Side::Buy, OrderType::GoodTillCancel, 101, 5});

      REQUIRE(trades.size() == 1);
      CHECK(trades[0].price == 100);
      CHECK(trades[0].quantity == 5);
      CHECK(book.size() == 0);
  }

  TEST_CASE("cancel removes a resting order") {
      Orderbook book;
      REQUIRE(book.add({1, Side::Buy, OrderType::GoodTillCancel, 99, 10}).empty());
      REQUIRE(book.cancel(1));
      CHECK_FALSE(book.cancel(1));
      CHECK_FALSE(book.bestBid().has_value());
  }

  REQUIRE stops the test case on failure; CHECK records the failure and
  keeps going. Python analogy: pytest's assert, with test functions
  registered by the TEST_CASE macro.

WHAT TO TEST IN AN ORDER BOOK (write each of these)
  - an order that doesn't cross just rests
  - a full fill, and a partial fill that leaves the remainder resting
  - one incoming order sweeping several price levels
  - FIFO at one price: the older order fills first
  - FillAndKill: rejected when it can't match; any remainder discarded
  - cancel: existing id, unknown id, the same id twice, the last order at
    a level (the level must disappear)
  - duplicate order ids are rejected
  - a zero-quantity order is rejected
  - best bid / best ask when empty

  Because the build uses -fsanitize=address,undefined, every test run
  also checks for memory bugs. With that setup, lesson 08's CancelOrder
  bug would have failed the first "cancel" test.

5. THE DESIGN (what your library should look like)
--------------------------------------------------------------------------------

This improves on the repo's design, for the reasons from lessons 05-13:

  struct Order { OrderId id; Side side; OrderType type; Price price;
                 Quantity remaining; };
  struct Trade { OrderId buyId; OrderId sellId; Price price; Quantity quantity; };

  class Orderbook {
  public:
      [[nodiscard]] std::vector<Trade> add(Order order);   // match, then rest
      bool cancel(OrderId id);                      // true if found
      std::optional<Price> bestBid() const;         // no magic -1
      std::optional<Price> bestAsk() const;
      std::size_t size() const;
  private:
      using Level = std::list<Order>;               // the list OWNS each Order
      std::map<Price, Level, std::greater<Price>> bids_;
      std::map<Price, Level, std::less<Price>>    asks_;
      std::unordered_map<OrderId, Level::iterator> index_;   // id -> exact spot

      template <typename Book>                      // works for either side
      void matchAgainst(Order& incoming, Book& opposite, std::vector<Trade>& trades);
  };

  Differences from the repo, and why:
    no shared_ptr         the book is the only owner (lesson 05)
    iterator-only index   O(1) cancel, no duplicated ownership (lesson 07)
    match, then rest      a crossed order never sits in the book (lesson 13)
    one trade price       the resting order's price (lesson 13)
    one template          removes the Buy/Sell code duplication (lesson 09)
    optional, bool        no magic values or silent returns (lessons 10, 12)
    no I/O at all         testable and benchmarkable (this lesson)

  A complete, compiled, and tested implementation of this design is in
  14b_reference_solution.txt. Try building it yourself first (lesson 16,
  milestone 1), then compare.

6. DAY-TO-DAY TOOLING
--------------------------------------------------------------------------------

  clangd (Cursor extension)  reads build/compile_commands.json. If clangd
                             can't find your headers, symlink it to the
                             project root:
                               ln -s build/compile_commands.json .
  lldb                       the debugger on macOS:
                               lldb ./build/orderbook_tests
                               (lldb) breakpoint set --name Orderbook::cancel
                               (lldb) run
  clang-format               automatic formatting (like black)
  clang-tidy                 a linter (like ruff/pylint) that catches many
                             bugs, including some use-after-move


PITFALLS
--------
- Forgetting #pragma once (redefinition errors).
- Defining non-inline functions in headers (duplicate symbol link errors).
- Putting everything in main.cpp "for now". That's how Server.cpp happened.
- Committing the build/ folder.
- Running tests without sanitizers.
- Forgetting to re-run cmake after adding a new .cpp file to CMakeLists.
