GOAL
----
- Internalize that C++ COPIES by default.
- Pass and return by value, by reference (&), by const reference
  (const &), and by pointer (*), and know when to use each.
- Understand the stack vs the heap.
- Recognize a dangling reference (the setup for lesson 08).


PYTHON VS C++  (read this twice)
--------------------------------
Python: EVERY variable is a reference to an object.
    a = [1, 2, 3]
    b = a            # b and a are the SAME list
    b.append(4)      # a is now [1, 2, 3, 4] too

C++: a variable IS the object. Assignment COPIES.
    std::vector<int> a{1, 2, 3};
    std::vector<int> b = a;      // b is a brand-new, independent copy
    b.push_back(4);              // a is still {1, 2, 3}

If you want Python-like sharing, you have to ask for it with & (reference)
or * (pointer). This is the biggest single mental shift from Python.


--------------------------------------------------------------------------------
1. THREE WAYS TO PASS AN ARGUMENT
--------------------------------------------------------------------------------

    void by_value(std::vector<int> v) { v.push_back(99); }   // gets a COPY
    void by_ref(std::vector<int>& v)  { v.push_back(99); }   // gets the ORIGINAL
    void by_ptr(std::vector<int>* v)  { if (v) v->push_back(99); } // gets an ADDRESS

    std::vector<int> a{1, 2, 3};
    by_value(a);   // a.size() == 3  (the copy was modified, then thrown away)
    by_ref(a);     // a.size() == 4
    by_ptr(&a);    // a.size() == 5  (&a = "the address of a")

(This exact program was compiled and run while writing the course; those
are the real outputs.)


--------------------------------------------------------------------------------
2. REFERENCES (&)
--------------------------------------------------------------------------------

A reference is an ALIAS: another name for an existing object.

    int x = 10;
    int& r = x;     // r IS x
    r = 20;         // x is now 20

Rules:
  - A reference must be initialized when created. There's no null reference.
  - A reference can't be re-pointed at something else later.
  - Using a reference is exactly like using the original (no special syntax).

const REFERENCE: THE WORKHORSE
    void print(const std::vector<int>& v);   // no copy, and can't modify

This is how you pass anything bigger than a few bytes (strings, vectors,
your own classes) when you only need to read it. Rule of thumb:

    small, cheap types (int, double, enum, pointer)  -> pass by value
    big types you only read                          -> const T&
    big types you need to modify                     -> T&
    something that might be "nothing"                -> T* (or std::optional)


--------------------------------------------------------------------------------
3. POINTERS (*)
--------------------------------------------------------------------------------

A pointer is a variable holding a memory ADDRESS.

    int x = 10;
    int* p = &x;       // p holds the address of x
    *p = 20;           // "dereference": follow the address. x is now 20
    int* q = nullptr;  // points at nothing (like None)

    Order o(1, 100, 10);
    Order* po = &o;
    po->GetId();       // -> means "dereference, then access the member"
    (*po).GetId();     // same thing, uglier

Pointers vs references:
  - Pointers can be null (nullptr) and can be re-pointed.
  - References can't be null and always refer to the same object.
  - Prefer references. Use pointers when "nothing" is a valid value, or
    when you need to re-point.

In modern C++ you should almost never write "new" and "delete" yourself.
Owning pointers are smart pointers (lesson 05). A raw pointer (T*) in
modern code usually means "I'm looking at this, but I don't own it."


--------------------------------------------------------------------------------
4. RETURNING VALUES AND REFERENCES
--------------------------------------------------------------------------------

RETURN BY VALUE (usually right)
    std::vector<int> make() { std::vector<int> v{1, 2, 3}; return v; }
  This is cheap. The compiler builds the result directly in the caller
  ("copy elision"), or moves it (lesson 05). Don't be afraid of it.

RETURN A const REFERENCE TO A MEMBER (a read-only view, no copy)
    class Book {
        std::vector<int> bids_;
    public:
        const std::vector<int>& GetBids() const { return bids_; }
    };
  Safe as long as the Book is alive.

NEVER RETURN A REFERENCE TO A LOCAL VARIABLE
    const std::vector<int>& broken() {
        std::vector<int> v{1, 2, 3};
        return v;          // v is destroyed when the function returns
    }                      // the caller holds a DANGLING reference
  Compilers usually warn about this simple case. They can't catch the
  complicated versions, and that's what lesson 08 is about.


--------------------------------------------------------------------------------
5. STACK VS HEAP
--------------------------------------------------------------------------------

STACK: local variables. Extremely fast to create. Automatically destroyed
when the scope ends. Limited size (usually a few MB).

    void f() {
        Order o(1, 100, 10);   // on the stack
    }                          // destroyed here, automatically

HEAP: memory you request explicitly. It lives until someone frees it.
Used when the object must outlive the current scope, when its size is
only known at runtime, or when it's huge.

    auto p = std::make_unique<Order>(1, 100, 10);   // on the heap (lesson 05)

Note that std::vector and std::string are small objects that can live on
the stack but keep their ELEMENTS on the heap, and manage that memory for
you.

Python puts every object on the heap and garbage-collects it. C++ lets
you choose, and the stack is the default.


--------------------------------------------------------------------------------
6. REFERENCES IN LOOPS (very common)
--------------------------------------------------------------------------------

    std::vector<std::string> names{"AAPL", "GOOG"};

    for (std::string n : names)        { ... }   // COPIES each string
    for (std::string& n : names)       { ... }   // modifies in place
    for (const std::string& n : names) { ... }   // read-only, no copy <- default
    for (const auto& n : names)        { ... }   // same, less typing

Default to "const auto&" in range-for loops over anything non-trivial.

PITFALLS
--------
- Forgetting & and silently modifying a copy (see Server.cpp:344 above).
- Taking a reference to something and then destroying it (lesson 08).
- Taking a reference to a vector element, then push_back-ing to the vector.
  The vector may reallocate, and your reference now points at freed memory
  (lesson 07).
- Passing big objects by value "because it works". It works, but it copies.
- Confusing the two meanings of & and *:
      int& r = x;    // in a declaration, & means "reference"
      int* p = &x;   // in an expression, & means "address of"
      int* p;        // in a declaration, * means "pointer"
      *p = 5;        // in an expression, * means "dereference"
