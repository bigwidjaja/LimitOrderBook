GOAL

- Write lambdas and choose capture modes correctly.

- Unpack pairs and structs with structured bindings.
- Write simple function and class templates.


PYTHON VS C++
-------------
Python lambdas are one-expression functions that capture variables from the
enclosing scope automatically, by reference.

C++ lambdas can be full multi-line functions, and you choose EXPLICITLY
what they capture and whether it's by copy or by reference. Getting that
wrong is a source of dangling-reference bugs (lesson 08 again).


--------------------------------------------------------------------------------
1. LAMBDA SYNTAX
--------------------------------------------------------------------------------

    [captures](parameters) -> return_type { body }
                              ^ optional, usually inferred

    auto add = [](int a, int b) { return a + b; };
    add(2, 3);   // 5

CAPTURES
    []          capture nothing
    [x]         copy x into the lambda (at creation time)
    [&x]        refer to x (sees later changes, and can modify it)
    [=]         copy everything used
    [&]         refer to everything used
    [this]      access the enclosing object's members

    int threshold = 100;
    auto above = [threshold](int p) { return p >= threshold; };

    int counter = 0;
    auto inc = [&counter] { ++counter; };
    inc(); inc();     // counter == 2

DANGER: capturing by reference and outliving the scope
    std::function<int()> make() {
        int local = 5;
        return [&local] { return local; };   // local dies when make() returns
    }                                        // the lambda now dangles: UB

  Rule: if a lambda might outlive the current scope (stored, returned,
  passed to a thread), capture BY VALUE.


--------------------------------------------------------------------------------
2. STANDARD ALGORITHMS
--------------------------------------------------------------------------------

Most take an iterator range [begin, end) plus optionally a lambda.

  #include <algorithm>
    std::sort(v.begin(), v.end());                                  // ascending
    std::sort(v.begin(), v.end(), [](const Order& a, const Order& b){
        return a.price < b.price; });                               // custom
    std::find(v.begin(), v.end(), 42);            // iterator, or end()
    std::find_if(v.begin(), v.end(), pred);
    std::count_if(v.begin(), v.end(), pred);
    std::any_of / all_of / none_of(v.begin(), v.end(), pred);
    std::min(a, b); std::max(a, b);
    std::min_element / max_element(v.begin(), v.end());
    std::transform(in.begin(), in.end(), out.begin(), func);

  #include <numeric>
    std::accumulate(v.begin(), v.end(), 0);       // sum, like Python's sum()
    std::accumulate(v.begin(), v.end(), init, [](auto acc, const auto& x){ ... });

Python equivalents: sorted(key=...), sum(), any(), all(), min(), max(),
map(), filter().

C++20 "ranges" let you skip the begin/end pairs:
    std::ranges::sort(v);
    std::ranges::count_if(v, pred);

THE accumulate TYPE TRAP
    std::vector<double> d{0.5, 0.5};
    std::accumulate(d.begin(), d.end(), 0);     // 0 is an int, so the result
                                                // is int: 0, not 1.0!
    std::accumulate(d.begin(), d.end(), 0.0);   // 1.0
  The type of the initial value decides the type of the result.


--------------------------------------------------------------------------------
3. STRUCTURED BINDINGS (C++17)
--------------------------------------------------------------------------------

Like Python tuple unpacking, but for pairs, tuples, structs, and map entries:

    std::pair<int, int> p{100, 105};
    auto [bid, ask] = p;                 // copies

    for (const auto& [price, orders] : bids_) { ... }   // map entries

    struct LevelInfo { Price price_; Quantity quantity_; };
    auto [price, qty] = someLevel;

With & they're REFERENCES into the original:
    auto& [askPrice, asks] = *asks_.begin();   // asks IS the list in the map

As lesson 08 showed, that means they can dangle if the original is
destroyed.


--------------------------------------------------------------------------------
4. TEMPLATES (the part this repo only USES, never WRITES)
--------------------------------------------------------------------------------

A template is a blueprint the compiler stamps out for each type you use it
with. std::vector<int> and std::vector<Order> are two separate classes
generated from one template.

FUNCTION TEMPLATE
    template <typename T>
    T clamp_to(T value, T lo, T hi) {
        return value < lo ? lo : (value > hi ? hi : value);
    }

    clamp_to(150, 0, 100);        // T = int
    clamp_to(1.5, 0.0, 1.0);      // T = double
    clamp_to(150, 0.0, 100);      // COMPILE ERROR: T can't be both int and double

CLASS TEMPLATE
    template <typename T>
    class Stack {
        std::vector<T> items_;
    public:
        void push(T x) { items_.push_back(std::move(x)); }
        T pop() { T x = std::move(items_.back()); items_.pop_back(); return x; }
        bool empty() const { return items_.empty(); }
    };

    Stack<int> s;  Stack<std::string> t;

Python analogy: duck typing, except it's checked at compile time and has
zero runtime cost. The downside is long error messages, and template code
usually has to live in headers (lesson 14).

C++20 CONCEPTS constrain templates and make the error messages readable:
    template <std::integral T>          // #include <concepts>
    T half(T x) { return x / 2; }
    half(3.5);   // error: "double does not satisfy integral"

A real use in YOUR project: the bid and ask sides of the order book are
nearly identical code with a different comparator. A member function
template can match against either side, with the side's map type as the
template parameter. The lesson 14 design does exactly that.

PITFALLS
--------
- [&] capture in a lambda that outlives the scope.
- accumulate's initial value type (0 vs 0.0 vs uint64_t{0}).
- Forgetting that the "end" iterator is exclusive.
- Writing templates before you need them. Make it work for one type first.
- Putting template definitions in a .cpp file and getting link errors
  (they belong in headers).
