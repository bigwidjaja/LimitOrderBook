GOAL
----
- Understand static typing and what "a type has a size" means.
- Use fixed-width integers correctly and know how they overflow.
- Use type aliases to give domain meaning to types.
- Use enum class instead of strings or magic numbers.
- Convert between types safely (static_cast, std::stoi and friends).


PYTHON VS C++
-------------
Python: a variable is a name pointing at an object, and the object knows
its own type. Integers grow as big as needed. You can write x = 5 and
later x = "hello".

C++: a variable IS a chunk of memory with a fixed type and a fixed size,
decided at compile time. An int32_t is exactly 4 bytes and can only hold
-2,147,483,648 to 2,147,483,647. Go past that and you get wraparound (for
unsigned types) or undefined behavior (for signed types).


--------------------------------------------------------------------------------
1. STATIC TYPES AND auto
--------------------------------------------------------------------------------

    int count = 5;
    count = "hello";        // COMPILE ERROR: can't assign a string to int

    auto price = 100;       // auto = "compiler, figure out the type" -> int
    auto name = std::string("AAPL");   // std::string

auto is NOT dynamic typing. The type is still fixed at compile time; you
just don't have to write it. Use auto when the type is obvious or very
long (like iterator types, lesson 07).


--------------------------------------------------------------------------------
2. FIXED-WIDTH INTEGERS (#include <cstdint>)
--------------------------------------------------------------------------------

Plain "int" and "long" have platform-dependent sizes. When size matters
(protocols, finance, file formats), use fixed-width types:

    std::int8_t   / std::uint8_t     1 byte
    std::int16_t  / std::uint16_t    2 bytes
    std::int32_t  / std::uint32_t    4 bytes   uint32 max ~4.29 billion
    std::int64_t  / std::uint64_t    8 bytes   uint64 max ~18 quintillion
    std::size_t                      unsigned; used for sizes and indexes

  "u" = unsigned: no negative numbers, double the positive range.

UNSIGNED WRAPAROUND (a real hazard in an order book)
    std::uint32_t remaining = 5, fill = 10;
    std::uint32_t result = remaining - fill;   // 4294967291, not -5!

  Unsigned arithmetic wraps around silently. That's why Order::Fill checks
  before subtracting (Server.cpp:89-96). Without that check, filling 10
  shares on a 5-share order would leave ~4 billion shares remaining.

SIGNED OVERFLOW IS UNDEFINED BEHAVIOR
    std::int32_t x = 2147483647;
    x = x + 1;    // undefined behavior: the compiler may assume this never happens

  More on undefined behavior in lesson 08.

WHY PRICES ARE INTEGERS, NOT FLOATS
    0.1 + 0.2 == 0.30000000000000004   (in Python AND C++)

  Floating-point can't represent most decimals exactly. Real exchanges
  store prices as integer "ticks" (e.g. 10123 = $101.23). This repo does
  the same: Price is int32_t.


--------------------------------------------------------------------------------
3. TYPE ALIASES WITH using
--------------------------------------------------------------------------------

    using Price    = std::int32_t;
    using Quantity = std::uint32_t;
    using OrderId  = std::uint64_t;

Now function signatures document themselves:
    void Fill(Quantity quantity);     // clearer than void Fill(uint32_t q)

And if you later decide prices need 64 bits, you change one line.

Caveat: an alias is just another name. The compiler will happily let you
pass a Quantity where a Price is expected. If you want the compiler to
catch that, you need a "strong type" (a small struct wrapping the value).
That's an advanced exercise for later.

Python equivalent: typing's "Price = int" (a hint only, never enforced).


--------------------------------------------------------------------------------
4. enum class
--------------------------------------------------------------------------------

    enum class Side { Buy, Sell };
    enum class OrderType { GoodTillCancel, FillAndKill };

    Side s = Side::Buy;
    if (s == Side::Sell) { ... }

Why "enum class" and not plain "enum"?
  - Scoped: you must write Side::Buy, so names don't leak or collide.
  - Strongly typed: a Side won't silently turn into an int, and you can't
    compare a Side with an OrderType.

    enum OldStyle { Red, Green };     // C-style: Red is just the int 0
    int n = Red;                      // compiles (bad)
    int m = Side::Buy;                // error with enum class (good)

  To get the number out on purpose: static_cast<int>(Side::Buy)

Python equivalent: class Side(Enum): BUY = 1; SELL = 2


--------------------------------------------------------------------------------
5. CONVERSIONS
--------------------------------------------------------------------------------

EXPLICIT CASTS
    double d = 3.9;
    int i = static_cast<int>(d);     // 3 (truncates)

  Use static_cast for normal conversions. Avoid C-style casts like (int)d;
  they are allowed but can silently do dangerous things. You'll rarely need
  reinterpret_cast or const_cast; treat them as red flags.

STRING -> NUMBER (#include <string>)
    std::stoi("42")     -> int
    std::stol / stoll   -> long / long long
    std::stoul / stoull -> unsigned long / unsigned long long
  These THROW an exception (lesson 10) on bad input ("abc") or overflow.

NUMBER -> STRING
    std::to_string(42)          -> "42"
    std::format("{}", 42)       -> "42"   (C++20, lesson 12)


IN THIS REPO
------------
  backend/engine/Server.cpp:23-32     the two enum classes
  backend/engine/Server.cpp:35-37     the Price/Quantity/OrderId aliases
  backend/engine/Server.cpp:89-96     Fill() guards against unsigned wraparound
  backend/engine/Server.cpp:495-522   parse_* functions: string -> typed value

  Look at parse_quantity (Server.cpp:513-517):
      uint32_t res = static_cast<uint32_t>(std::stoul(quantity));
  std::stoul returns unsigned long, which is 64 bits on your Mac. Casting to
  uint32_t silently chops off the top bits. So quantity "5000000000"
  becomes 705032704, and there's no error. Exercise 3 asks you to fix it.

  Look at parse_side (Server.cpp:500-503):
      if (side=="BUY") return Side::Buy; else return Side::Sell;
  ANY string other than "BUY" (like "buy" or "banana") becomes Sell.
  That's a correctness bug waiting to happen.


PITFALLS
--------
- Mixing signed and unsigned in comparisons:
      int i = -1; unsigned u = 1;
      if (i < u)   // FALSE! i is converted to a huge unsigned number
  -Wall -Wextra warns about this (-Wsign-compare).
- Using float/double for money.
- Assuming int is always 32 bits or long is always 64 bits.
- Using strings where an enum belongs.

   std::numeric_limits<std::uint32_t>::max() (from <limits>) instead of

   anything else. Use std::invalid_argument.

   Compile with -Wall and delete one case: notice that the compiler warns
   you that the switch doesn't handle every value. Python can't do that.
