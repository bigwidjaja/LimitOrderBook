================================================================================
  STEP BY STEP  — paste ONLY the current milestone
================================================================================

Build in a new repo named mdkit. One milestone at a time. "Done" means
tests pass under ASan+UBSan (Linux/macOS) and the checkpoint at the
bottom of the milestone is answered without notes.

Do not skip to Python, IEX, or sockets. M1-M3 are the learning core.

--------------------------------------------------------------------------------
M0  TOOLCHAIN
--------------------------------------------------------------------------------
Student does:
  - clang++ or g++ that accepts -std=c++20 and std::format / std::span.
    Apple Clang 14 is too old. Install a newer LLVM or Xcode CLT.
  - cmake, ninja optional.
  - Empty repo, C++20, -Wall -Wextra -Wpedantic, sanitizers ON in Debug.
  - Catch2 via FetchContent. One dummy TEST_CASE that fails, then passes.
  - .gitignore: build/, *.pcap, *.ITCH*, data/

Done when: ctest runs one test. No parser code yet.

--------------------------------------------------------------------------------
M1  ENDIAN + ITCH DECODE + mdcat ON A FIXTURE
--------------------------------------------------------------------------------
Order of slices. Stop after each until tests are green.

  1. endian.hpp: load_be, load_le, load_be48. Tests: 0x01020304,
     a 6-byte timestamp, a Price4 round-trip through bytes.
  2. types: Price4 = uint32, OrderRef = uint64, Side enum class,
     Symbol = array<char,8> with a trimmed string_view. No std::string.
  3. Test encoder that writes one 'A' message including the 2-byte
     length. Student computes the 36 bytes on paper first.
  4. decode_message for 'A' only. Handler concept + IgnoreRest.
     Wrong length -> on_error, no throw.
  5. decode_stream over a buffer of several frames. Truncated tail
     returns bytes consumed, does not error.
  6. Add 'E', 'X', 'D', 'U' the same way: encoder test, then decoder.
     One type per session.
  7. mdcat: CLI11, read a file into a vector (mapping comes in M3),
     print type, locate, ref, side, shares, symbol, price with 4 decimals.
     Flags: --limit N.

Done when:
  - Round-trip test for A,E,X,D,U.
  - A buffer with a bad length and an unknown type increments errors
    and does not crash under ASan.
  - mdcat on the fixture prints AAPL and 150.0000, not 150.60.

Checkpoint: why is the symbol a string_view into the message bytes,
and when does that view become invalid?

--------------------------------------------------------------------------------
M2  ITCH BOOK + mdstat + mdbook
--------------------------------------------------------------------------------
Slices:
  1. Book: add(side, price, shares), reduce(side, price, shares, dropOrder).
     Unit test with no feed. Bids are map with greater<>.
  2. ItchBookBuilder : IgnoreRest. vector<Book>(65536).
     unordered_map<OrderRef, Live>. Implement Add only. Test two
     orders at the same price: shares sum, order count is 2.
  3. Exec and Cancel. Partial fill leaves the order. Full fill erases
     the level. Cancel of one of two orders leaves the other.
  4. Delete and Replace. Replace keeps side from the old order.
     Unknown ref increments a counter. Over-execute clamps.
  5. The scenario that must pass exactly:
       locate 7: buy 100 @ 1500000, buy 50 @ 1500000,
       sell 30 @ 1501000, exec 40 of the first, cancel the second,
       replace the sell with 20 @ 1502000, delete ref 99.
       Bid 1500000 x 60, 1 order. Ask 1502000 x 20, 1 order.
       live orders 2. unknown refs 1.
  6. mdstat: counts by type, errors, unknown refs. Exit 0.
  7. Stock Directory 'R' FROM THE PDF, then a locate->symbol table.
     mdbook FILE --symbol AAPL prints top 5 levels. Without 'R',
     mdbook --locate N is acceptable as a stepping stone.

Done when that scenario is a Catch2 test and mdbook matches it.
Checkpoint: why does Replace not trust a side byte, and why is
orders_.erase after you have copied the Live fields you still need?

--------------------------------------------------------------------------------
M3  BIG FILES + A NUMBER
--------------------------------------------------------------------------------
Slices:
  1. MappedFile. POSIX mmap. Destructor unmaps. Test on a 64-byte file.
     #ifdef _WIN32 MapViewOfFile in the same class, nowhere else.
  2. Point decode_stream at file.bytes(). Confirm a string_view is not
     stored past the MappedFile's life.
  3. mdbench, Release, no sanitizers: parse-only msgs/sec and
     parse+book msgs/sec. Generate orders BEFORE the timer only if
     you are synthesizing; for a real file, time the walk.
  4. Download ONE Nasdaq sample from emi.nasdaq.com. Do not commit it.
     Run mdstat and mdbench. Write the numbers in README.
  5. Only after the number exists: reserve the hash map. Re-bench.
     Do not rewrite the decoder for speed before profiling.

Done when README has machine, file, message count, two rates.
Checkpoint: what did the profiler say, or why did you not need one?

--------------------------------------------------------------------------------
M4  SECOND FEED (IEX)
--------------------------------------------------------------------------------
Slices:
  1. Read the IEX transport PDF and the DEEP spec version in the
     filename. Write the header offsets YOU confirmed next to
     05_binary_contracts.txt. Reject the task if they differ and you
     cannot say why.
  2. Tiny pcap fixture: one UDP packet, one IEX-TP segment, one
     price-level message. Parser test.
  3. Walk message count. Sequence gap counter.
  4. IexBookBuilder: level updates only. No order-id map.
  5. normalize::Event variant. mdconvert --out x.csv for both feeds,
     same columns: ts, symbol, kind, side, price, size, ref (blank
     for IEX).

Done when mdstat on a real HIST file prints counts and exits 1 if
you inject a gap in the fixture.
Checkpoint: why can't the ITCH orders_ map be reused for DEEP?

M5  PYTHON
--------------------------------------------------------------------------------
  pybind11 module. mdkit.read(path) yields events without building a

--------------------------------------------------------------------------------
M6  PICK ONE STRETCH
--------------------------------------------------------------------------------
  A. mdreplay + mdlisten: UDP multicast, one thread receives, one
     decodes, BlockingQueue between them. ThreadSanitizer clean.
  B. libFuzzer target: decode_stream on random bytes, ASan, no crash.
  C. mdsnap: replay a fixture, GET /book?symbol=AAPL returns JSON.
     cpp-httplib. Not on the hot path.

Capstone README: diagram, spec links, benchmark table, CI badge for
Ubuntu and Windows, one paragraph on sequence gaps.
