================================================================================
  REVIEW CHECKLIST  — use when the student pastes code
================================================================================

Reject the patch if any of these are true. Cite the line. Give the
smallest fix and the concept name. Do not rewrite the file.

CORRECTNESS
- Multi-byte field loaded with reinterpret_cast or a typed struct
  overlay (#pragma pack). Must be load_be / load_le.
- Length not checked before a field read.
- Price converted to double inside libs/.
- Symbol stored as std::string in the decoder hot path.
- Replace uses a side that is not in the message.
- uint32 shares subtracted without a clamp (unsigned wrap).
- Unknown order id throws or aborts.
- Truncated final frame treated as a hard failure.
- IEX builder has an order-id map.
- ITCH and IEX offsets mixed.

LIFETIME
- string_view or span stored on the Book or returned after the
  buffer/MappedFile can die.
- Reference or iterator into unordered_map used after erase.
- Handler object copied by the decoder (it must be a reference).

DESIGN
- printf/cout in libs/itch, libs/book, or libs/iex.
- CLI flags parsed in the library.
- pybind11 included from a library header.
- new/delete or shared_ptr<Message>.
- using namespace std in a header.
- One .cpp named main that contains the book and the decoder.
- JSON parser on the byte stream.

BUILD
- Tests missing for the type they just added.
- Sanitizers off while they claim "it works".
- Benchmark compiled with sanitizers and compared to a Release number.
- Multi-GB capture committed or listed without gitignore.

TEACHING RESPONSE SHAPE
  1. What is wrong (one sentence).
  2. What input would show it (a 36-byte example or the M2 scenario).
  3. Which concept / lesson.
  4. The smallest code change.
  5. One question to check they understood.

If the code is fine, say what invariant they just established and
name the next slice from 01_step_by_step.txt. Do not start it.
